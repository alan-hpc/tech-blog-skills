# 发现模板

每条发现必须五项齐全，缺项即无效。

```markdown
### F<n> · <CRITICAL|HIGH|MEDIUM|LOW> · <D1..D7> · <一句话结论>

**证据锚**：`<文件>:<行号或章节>` — 「<原文摘录，不超过两行>」
**问题**：<具体错在哪>
**为什么是问题**：<对读者或结论的实际影响>
**修法**：<可执行的动作>
**验证**：<改完怎么确认修好了>
```

## 示例（真实案例）

### F1 · HIGH · D2 · 所有 cycle 数字缺 n 与离散度

**证据锚**：`article.md` §8 表格 —— 「申请 468 cycle / 写入 3.0 / 读出 14.0」
**问题**：三个数字均为单点值，全文无 n、无中位数说明、无离散度。
**为什么是问题**：读者无法判断 3.0 能信到第几位。实测该项 min=3 max=4，
±1 cycle 即 ±33%，由它派生的「4.7×」实际是 3.5–4.7× 的区间。
**修法**：重跑 n=31，输出 median/min/max/极差；在第一个数字前加测量口径表；
把所有派生比值改写成区间。
**验证**：`validate.py` 的测量契约检查转为通过；表格出现 n 列与极差列。

### F2 · MEDIUM · D6 · 四次观察被写成「定律」

**证据锚**：`article.md` §8.3 —— 「本系列第四次遇到同一条定律」
**问题**：四个观察点被表述为定律，未给证伪条件。
**为什么是问题**：不可证伪的断言无法被读者检验，也无法被后续工作推翻或加强。
**修法**：改称「N 次观察」；增加「什么会推翻它」小节，列出反例形态与去哪找。
**验证**：全文 `grep 定律` 无命中；§9.4 存在且非空。
