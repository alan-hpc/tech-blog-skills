# 五席位评审 · 面向 codesign 技术报告

**只读。** 本技能产出发现清单，**不改文章**。修复由 `codesign-article` 执行。
理由：评审者动手改，就失去了独立判断的位置。

---

## 1 · 评审的七个维度

| 维度 | 问题 | 不满足的典型形态 |
|---|---|---|
| **D1 问题定义** | 这篇要回答的问题够不够尖锐、可证伪？ | 「介绍一下 X」式的综述，没有待答问题 |
| **D2 测量效度** | 每个数字是否满足测量契约？ | 单点值、无 n、无离散度、无反自欺核对 |
| **D3 链条完整** | 软件 → ISA → 汇编 → 微架构 → 物理实现，中间有没有断？ | 讲完 API 直接跳「因为硬件这样设计」 |
| **D4 证据分级** | 每条承重断言的证据等级是否显式且正确？ | 二手博客当一手事实；「据原文」实为「据摘要」 |
| **D5 可复现** | 读者能否重建每个数字与每张图？ | 环境未固定、源码未给、图无出处 |
| **D6 边界与证伪** | 说清了什么没验证、什么会推翻结论吗？ | 把 N 次观察写成「定律」而不给证伪条件 |
| **D7 结构与术语** | 是否符合骨架？术语首现是否解释？ | 术语堆砌、结论埋在末尾 |

**判定词只有四个**：`满足` / `部分满足` / `不满足` / `未评估`。
证据不支持时就写 `不满足`，**不因为怕冲突而抬高判定**。

## 2 · 五个席位

每个席位从**自己的角度**独立过一遍全文。
**不要为了避免与其它席位重复而略过发现** —— 重复出现的问题恰恰是强信号，
去重是汇总阶段的事。

### 席位 1 · 复现者（Reproducer）

只问一件事：**我能不能照着这篇文章把每个数字重跑出来？**

- 环境固定了吗（型号、驱动、runtime、时钟、独占性）
- 编译命令完整吗
- 源码在哪，能拿到吗
- 图表的数据来源标了吗
- **随机抽一个数字，尝试从文章内容重建它的计算路径**；重建不出就是发现

### 席位 2 · 微架构审稿人

- 对硬件行为的解释，有没有一手依据（规范 / 专利正文 / 官方文档）？
- 有没有把「观察到的现象」直接说成「硬件的实现方式」？
- 跨尺度类比是否成立（口径一致吗、量纲一致吗）？

### 席位 3 · ISA / 编译器审稿人

- PTX / 汇编的读法对不对？助记符拆解是事实还是推断？
- 编译目标、优化等级会不会改变结论？
- 「手册没有但专利有」的特性，是否去工具链验证过？

### 席位 4 · 领域外读者（Outsider）

- 每个术语首次出现时解释了吗？
- 不了解该架构的人能读到第几段？
- 结论是否在开头就给出，还是埋在末尾？

### 席位 5 · 魔鬼代言人（Devil's Advocate）—— 不可省略

**任务：构造「中心论点是错的」的最强论证。**

- 中心论点如果错，最可能错在哪一步？
- 有没有选择性取样？（只举支持的例子）
- 有没有更简单的解释能覆盖同样的观测？
- 作者最不愿意被问的问题是什么？

**铁律**：魔鬼代言人提出的 `CRITICAL` 发现，**必须逐条被显式裁决**。
可以判定「已被文章其它部分回应」并记录理由，
**但不能默默跳过**。未裁决的 CRITICAL 直接阻断发布。

## 3 · 发现的格式

每条发现都必须完整，缺项即无效：

```markdown
### F<n> · <严重度> · <维度> · <一句话结论>

**证据锚**：<文件>:<行号或章节> — 「<原文摘录>」
**问题**：<具体错在哪，一句话>
**为什么是问题**：<对读者/结论的实际影响>
**修法**：<可执行的具体动作，不是「建议加强」>
**验证**：<改完之后怎么确认修好了>
```

**严重度：**

| 级别 | 含义 | 处置 |
|---|---|---|
| `CRITICAL` | 结论错误，或数字可能是虚构的 | **阻断发布** |
| `HIGH` | 无法复现，或证据等级被抬高了 | 发布前必修 |
| `MEDIUM` | 精度被高估、边界未说明、链条有缺口 | 应修 |
| `LOW` | 术语、措辞、格式 | 可延后 |

**禁止的发现形态**（这些是无效发现，不要写）：

| 反模式 | 为什么无效 |
|---|---|
| 「方法论可以更严谨」 | 没说哪里、怎么改 |
| 「建议补充更多实验」 | 没说补什么实验、验证什么 |
| 凑数量的发现 | 发现数量不是质量指标 |
| 为了平衡而制造的优点 | 优点要跟着证据走 |
| 评审者直接改文章 | 越界；本技能只读 |

## 4 · 执行顺序

```
1. 通读一遍，不记录        ← 先建立整体印象，避免逐句挑刺失焦
2. 五席位各自过一遍        ← 每席位独立，不互相看
3. 汇总去重，标注重复出现  ← 多席位共同命中 = 强信号
4. 魔鬼代言人的 CRITICAL 逐条裁决
5. 按严重度排序，输出清单
6. 给出一句总体判定
```

**总体判定只有三种**：

- `可发布` —— 无 CRITICAL / HIGH
- `修后可发布` —— 有 HIGH，但都有明确修法
- `需返工` —— 有 CRITICAL，或 D2/D3 整体不满足

## 5 · 快速自检（写作者自用）

不跑完整评审时，至少过这九条：

- [ ] 每个数字都有 n 和离散度吗
- [ ] 每个被测指令都在汇编里数过条数吗
- [ ] 环境（型号/驱动/时钟/独占性）写进文章了吗
- [ ] 每条承重断言的证据等级标了吗
- [ ] 「据原文」的地方，我真的读到原文了吗
- [ ] 推断都标成推断了吗
- [ ] 有没有把 N 次观察写成「定律」
- [ ] 「我没验证的」那一节，覆盖全了吗
- [ ] 术语首现都解释了吗

**任何一条答不上来，就先别发。**

## 6 · 与其它技能的关系

- 上游 [`codesign-article`](../codesign-article/SKILL.md)：评审对象。
- D2 的判据来自 [`codesign-measure`](../codesign-measure/SKILL.md) 的测量契约。
