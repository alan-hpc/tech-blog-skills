# 架构

## 数据流

```
素材                 测量                  文章                  评审
────                 ────                  ────                  ────
codesign-sources     codesign-measure      codesign-article      codesign-review
      │                    │                     │                     │
      │ SOURCES.md         │ *.jsonl             │ 九段式 md            │ 发现清单
      │ + 证据等级          │ + 测量口径           │                     │ + 严重度
      │ blogs/figures/     │ + sass_check        │                     │ + 修法
      ▼                    ▼                     ▼                     │
      └────────────────────┴─────────────────────┘                     │
                           │                                           │
                           └───────────── 未通过则回流 ◀────────────────┘
```

## 各层负责的失败模式

| 层 | 拦截的失败 |
|---|---|
| sources | 二手当一手、只读权利要求就说读过专利、抓不到正文却写「据原文」 |
| measure | 编译器优化掉被测代码、单点值、共享机器污染、分辨率边缘过度精确 |
| article | 术语堆砌、结论埋末尾、示意汇编与真实代码对不上、事实与推测混写 |
| review | 不可证伪的断言、链条断裂、选择性取样、精度高估 |

## 质量闸门的分工

| 检查 | 由谁做 | 为什么 |
|---|---|---|
| 代码块配平、链接可达、图片存在 | `shared/validate.py` | 机械可判 |
| 测量契约字段是否齐全 | `shared/validate.py` | 关键词可判 |
| 九段式章节是否完整 | `shared/validate.py --strict` | 标题可判 |
| 论证是否成立、解释是否正确 | `codesign-review` 五席位 | **机器判不了** |
| 中心论点是否可能是错的 | 魔鬼代言人席位 | **机器判不了** |

`validate.py` 全绿**不等于**可以发布 —— 它只保证机械层面无缺陷。

## 证据等级贯穿全流程

E0 实测 / E1 一手规范 / E2 厂商博客 / E3 社区博客 / E4 仅摘要 / E5 推断

等级在 `codesign-sources` 确定，在 `codesign-article` 用措辞体现，
在 `codesign-review` 的 D4 维度被检查。**三处必须一致。**
